# Calendar design experiment

Opt-in `/experiment.html` reuses authentication, API, filters and detail data from the current application. `/experiment.html?demo=1` offers explicitly synthetic rides for visual review without login. Existing homepage stays available.

Acceptance: seven weekday columns on desktop; chronological single column below 1000px; compact cards with club, start time, distance and elevation when present; terrain and skill in the modal; accessible modal details; previous/next month and today; continuous week scrolling in both directions without losing position when prepending. No calendar/list switch in the experiment.

Implementation: native ES modules and CSS, no framework or build migration for this exploratory slice. A custom calendar renderer exposes the small interface already used by the coordinator. Weeks extend on scroll; event data comes from the existing upcoming-events endpoint, which does not support historical month queries. No invented route profiles or implied historical availability.

Verification: date/card regression tests, default suite, desktop/mobile browser smoke. React/component-library selection remains a later decision once this interaction has been reviewed.

Verified: 121 default checks pass on owner-permitted Node 26; Chrome smoke checks demo rendering at 320/768/1024/1440px, no horizontal overflow, navigation, bidirectional week extension and details with no JS errors. Live OAuth/Strava was not exercised. Week DOM currently grows while exploring; virtualization and range-based backend loading are follow-up work before replacing the primary calendar. Demo intentionally does not expose account filters.
